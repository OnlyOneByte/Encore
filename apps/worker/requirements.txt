# EXPLICIT, not incidental: torchaudio 2.8 ships NO audio-write backend of its own, so demucs's
# save_audio() raises "Couldn't find appropriate backend to handle uri .../vocals.wav" — AFTER
# separating to 100%. soundfile arrives transitively via whisperx, so the full install hid this and
# only a stems-only worker (capabilities=stems, no align) hit it. The failure is maximally
# misleading: three attempts each burn a full separation pass, and with the job's error only sent
# over the wire the song just sat at "separating 100%" forever. Pin it here so `stems` alone works.
soundfile>=0.13
# WhisperX — forced-alignment mode: we feed it KNOWN lyrics text (from LRCLIB) + audio and
# use its wav2vec2 align() to produce WORD timings, rather than trusting ASR to transcribe sung
# vocals. 3.8.6 is the modern line that installs on py3.12 and matches faster-whisper 1.2's API.
whisperx==3.8.6
# pyannote.audio — SPEAKER DIARIZATION for duet part attribution (issue #691). It already arrives
# TRANSITIVELY via whisperx 3.8.6 (which pins pyannote-audio>=4, see the coupled version-set note
# above); pinned EXPLICITLY here — the soundfile precedent — because the `diarize` capability now
# depends on it directly, so its version is ours to control, not an incidental of whisperx's resolver.
# Only a worker that advertises `diarize` loads it (the pipeline is HF-gated and lazy-imported), so a
# demucs/align-only box never pays its startup cost. 4.0 is the line whisperx 3.8.6 resolved on the
# pinned torch 2.8 / py3.12 stack — do NOT re-pin without re-resolving the whole ML set.
pyannote.audio==4.0.0

# python-audio-separator — the MEL-BAND RoFormer engine, adopted ALONGSIDE bs-roformer-infer (issue
# #483, owner ruling Q1(b): both engines, not one over the other — docs/DECISIONS.md). It reaches the

# only model_type=='bs_roformer' and ships no mel_band module), running them as a first-class MDXC path.

# no GPU (docs/benchmarks/SUMMARY.md §4). Only a worker that advertises the `stems:audiosep` capability
# loads it (capabilities.py probes for it), so the default (demucs-only) worker never pays its startup
# cost. Pinned like everything else here (no bare latest); NOT the `[cpu]` extra, which pins its own
# torch — this rides the existing torch 2.8 set above, adds no numpy rebuild.
python-audio-separator==0.47.0

# ── lyrics line-splitting ──────────────────────────────────────────────────────────────
# `karaoke-lyrics-processor` supplies the LENGTH-BOUNDING half of re-lineating an ASR blob (hard char
# budget with an iteration cap, nested-parenthesis isolation, punctuation cleanup); src/lyrics_presplit
# supplies the boundary half, which upstream measurably gets wrong. It is installed --no-deps in the
# Dockerfile, NOT listed here, because of what its own dependency list drags in:
#
#   MEASURED 2026-09-03 (`pip install --dry-run` against this venv): 30 packages, 29 of them unused.
#   `textract-py3` roots almost all of it — SpeechRecognition, pdfminer.six, python-pptx, extract-msg
#   → oletools + pcodedmp (a VBA macro deobfuscator), cryptography, easygui (Tkinter), xlrd pinned
#   <2.0, ebcdic — and `python-docx`, which is DECLARED but never imported anywhere in upstream's
#   source, solely drags lxml. All of it serves .doc/.docx/.rtf ingestion and a clipboard copy: two
#   features we never call, since our text arrives in memory from an HTTP response or from whisper.
#   pip did resolve the full tree cleanly against the torch/whisperx set above — this is unused weight
#   and supply-chain surface, not a version conflict.
#
# These three ARE imported at upstream's module top level and each has zero transitive dependencies,
# so they are cheaper to install for real than to stub. The one remaining top-level import, `textract`,
# is stubbed in src/lyrics_presplit._load_klp.
pyperclip==1.11.0
docx2txt==0.9
striprtf==0.0.33
